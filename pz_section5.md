## 5 Руководство пользователя

Разработанное программное средство предназначено для автоматизации основных процессов агентства недвижимости: ведения базы объектов, собственников и клиентов, регистрации сделок купли-продажи и аренды, формирования отчетов и контроля действий пользователей. Работа с системой выполняется через веб-интерфейс, что упрощает эксплуатацию программного средства и не требует установки отдельного клиентского приложения на каждое рабочее место.

Пользователь взаимодействует с системой с помощью браузера, а все данные хранятся в базе данных PostgreSQL. Обработка запросов, проверка корректности вводимых данных, разграничение прав доступа и отображение результатов выполняются серверной частью приложения. Вследствие этого для штатной эксплуатации необходимо обеспечить запуск базы данных, серверной части приложения и доступ пользователя к локальному или сетевому адресу веб-приложения.

Назначение и условия применения программы. Программное средство по теме «Программное средство для организации деятельности агентства недвижимости города» предназначено для решения следующих задач:

- учет объектов недвижимости с классификацией по категориям, статусам, состояниям и районам;
- ведение реестра собственников объектов;
- ведение клиентской базы покупателей и арендаторов;
- регистрация и сопровождение сделок купли-продажи и аренды;
- формирование аналитических отчетов;
- просмотр журнала действий пользователей;
- выполнение административных операций сопровождения базы данных.

Для работы с системой требуется:

- операционная система Windows;
- установленный сервер PostgreSQL;
- клиентские утилиты PostgreSQL `psql`, `pg_dump`, `pg_restore`;
- установленный Rust и инструмент `cargo` для локального запуска приложения;
- любой современный веб-браузер;
- настроенный файл окружения `.env` с параметрами подключения к базе данных.

При стандартной конфигурации приложение запускается по адресу `http://127.0.0.1:8080`. Значения имени приложения, адреса и порта могут быть изменены в файле `.env` с помощью параметров `APP_NAME`, `APP_HOST`, `APP_PORT`. Параметр `DATABASE_URL` задает строку подключения к PostgreSQL.

Подготовка к работе и запуск программы. Перед началом работы необходимо подготовить локальное окружение и инициализировать базу данных.

Для автоматизации первичной настройки проекта используется PowerShell-скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-local.ps1
```

Данный сценарий выполняет проверку наличия внешних инструментов, создает файл `.env`, если он отсутствует, и подготавливает параметры запуска приложения. При использовании стандартной конфигурации файл `.env` должен содержать адрес приложения и строку подключения к базе данных, например:

```env
APP_NAME=RealtyFlow
APP_HOST=127.0.0.1
APP_PORT=8080
DATABASE_URL=postgres://postgres:postgres@localhost:5432/realty_agency
```

После подготовки окружения необходимо создать и заполнить базу данных. Для этого используется сценарий:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/init_db.ps1
```

Указанный скрипт:

- проверяет наличие базы данных `realty_agency`;
- при необходимости создает ее;
- последовательно применяет SQL-файлы схемы, тестовых данных, представлений, триггеров и ролей.

Если требуется выполнить инициализацию вручную, SQL-файлы следует запускать в следующем порядке:

```powershell
psql -U postgres -d realty_agency -f sql/01_schema.sql
psql -U postgres -d realty_agency -f sql/02_seed.sql
psql -U postgres -d realty_agency -f sql/03_views_and_automation.sql
psql -U postgres -d realty_agency -f sql/04_roles.sql
```

После подготовки базы данных приложение запускается командой:

```powershell
cargo run
```

После успешного запуска в терминале отображается сообщение о старте сервера, а приложение становится доступным по адресу, указанному в параметрах `APP_HOST` и `APP_PORT`.

Вход в систему и завершение работы. После открытия стартовой страницы пользователь переходит на экран авторизации. Для входа необходимо ввести логин и пароль в соответствующие поля формы и нажать кнопку «Войти». В демонстрационной версии проекта предусмотрены тестовые учетные записи:

- администратор: `admin / admin123`;
- риелтор: `realtor / realtor123`;
- гость: `guest / guest123`.

Дополнительно в базе сохранены учетные записи `manager / manager123` и `analyst / analyst123`, используемые для совместимости с предыдущими версиями проекта.

При успешной аутентификации пользователь перенаправляется на панель управления. При вводе неверных учетных данных система выводит сообщение об ошибке и не предоставляет доступ к защищенным разделам приложения.

Для завершения работы необходимо нажать кнопку «Выйти» в правой части верхней панели. После этого сеанс пользователя завершается, а система возвращает его на страницу входа.

Роли пользователей определяют доступные возможности:

- администратор имеет полный доступ к разделам системы, отчетам, журналу аудита и административному SQL-режиму;
- риелтор может просматривать и изменять данные по объектам, собственникам, клиентам и сделкам, а также формировать отчеты;
- гость работает только в режиме просмотра и не может изменять данные.

Работа с основными разделами программы. После входа в систему пользователь попадает на панель управления. На стартовом экране отображаются основные сводные показатели: количество объектов, число свободных объектов, количество клиентов, число активных сделок и поступления за месяц. Ниже выводится таблица последних сделок. Данный экран предназначен для быстрого контроля текущего состояния агентства и перехода к основным разделам программы.

Раздел «Объекты». Раздел «Объекты» предназначен для ведения каталога недвижимости. В верхней части страницы располагается форма поиска и фильтрации. Пользователь может выполнить поиск по названию или адресу объекта, а также установить фильтры по категории, статусу и району.

Для добавления нового объекта пользователю с правами редактирования необходимо заполнить форму «Новый объект». В карточке указываются:

- название объекта;
- собственник;
- категория;
- статус;
- состояние;
- район;
- площадь;
- стоимость;
- адрес;
- описание.

После нажатия кнопки «Сохранить объект» запись добавляется в базу данных и отображается в списке объектов. В нижней части страницы расположен табличный реестр, из которого можно перейти к редактированию или удалению записи. Для изменения данных необходимо нажать кнопку «Изменить», внести новые значения в форму редактирования и сохранить изменения.

Раздел «Собственники». Раздел «Собственники» содержит реестр владельцев недвижимости. Он используется для хранения контактной и идентификационной информации о владельцах и обеспечивает связь объектов с конкретными собственниками.

Для создания новой записи необходимо заполнить форму, указав:

- ФИО;
- телефон;
- адрес электронной почты;
- паспортные данные;
- примечание.

После сохранения запись появляется в общем реестре собственников. Из таблицы пользователь может перейти к редактированию карточки или удалить запись, если она больше не используется в системе. Следует учитывать, что удаление данных, связанных с другими сущностями, ограничивается правилами ссылочной целостности базы данных.

Раздел «Клиенты». Раздел «Клиенты» предназначен для ведения базы покупателей и арендаторов. В форме добавления нового клиента указываются:

- тип клиента;
- ФИО;
- телефон;
- адрес электронной почты;
- бюджет;
- предпочитаемая категория недвижимости;
- примечание.

После сохранения запись добавляется в таблицу клиентов и может использоваться при оформлении сделок. Для каждой записи доступны операции редактирования и удаления. При вводе некорректных данных, например отрицательного бюджета или пустых обязательных полей, система выводит сообщение об ошибке и не выполняет сохранение.

Раздел «Сделки». Раздел «Сделки» используется для регистрации операций купли-продажи и аренды. Для создания сделки пользователю необходимо выбрать объект, клиента, тип сделки и статус, а затем указать сумму, дату начала, дату окончания и примечание.

Особенностью данного раздела является то, что часть бизнес-логики реализована на стороне базы данных:

- комиссия агентства рассчитывается автоматически;
- проверяется доступность объекта на указанный период;
- предотвращается создание конфликтующих сделок;
- статус объекта недвижимости изменяется в зависимости от состояния сделки.

После регистрации сделка отображается в журнале сделок с указанием объекта, клиента, менеджера, типа, статуса, суммы, комиссии и дат. Если требуется изменить параметры сделки, пользователь может открыть форму редактирования из списка сделок. При повторном сохранении комиссия пересчитывается автоматически, а ограничения базы данных применяются повторно.

Раздел «Отчеты». Раздел «Отчеты» предназначен для просмотра аналитической информации по данным системы. В текущей версии приложения пользователю доступны следующие предопределенные отчеты:

- каталог объектов;
- портфель собственников;
- продажи по месяцам;
- эффективность менеджеров.

Каждый отчет выводится в табличном виде непосредственно на странице. Пользователь может:

- просмотреть отчет на экране;
- отправить отчет на печать с помощью кнопки «Печать»;
- экспортировать отчет в формат `CSV`;
- экспортировать отчет в Excel-совместимый формат `XLS`.

Для администратора в этом же разделе доступен режим выполнения произвольных SQL-запросов. В специальное текстовое поле вводится запрос чтения, после чего нажимается кнопка «Выполнить запрос». Система принимает только инструкции `SELECT`, `WITH` и `VALUES`. Результат запроса отображается в табличной форме и при необходимости может быть экспортирован в `CSV` или `XLS`.

Раздел «Журнал действий». Раздел «Журнал действий» доступен только администратору. Он предназначен для просмотра последних событий в системе и содержит сведения о пользователе, типе действия, затронутой сущности, деталях изменения, а также дате и времени операции.

Данный раздел позволяет контролировать:

- вход и выход пользователей из системы;
- добавление, изменение и удаление записей;
- изменения, фиксируемые триггерами базы данных.

При необходимости журнал также может быть экспортирован в форматы `CSV` и `XLS`.

Выполнение служебных операций. Для сопровождения базы данных в проект включены отдельные PowerShell-скрипты резервного копирования и восстановления.

Создание резервной копии выполняется командой:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/backup.ps1
```

По умолчанию резервная копия сохраняется в каталог `backups` в формате PostgreSQL dump. Имя файла содержит временную метку, что позволяет хранить несколько копий базы данных.

Для восстановления базы данных из резервной копии используется команда:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/restore.ps1 -BackupFile .\backups\имя_файла.dump
```

При выполнении восстановления необходимо указать путь к ранее созданному файлу резервной копии. Восстановление выполняется с помощью утилиты `pg_restore`.

Следует учитывать, что данные операции относятся к административным. Их рекомендуется выполнять только пользователю, ответственному за сопровождение базы данных и имеющему необходимые права доступа к PostgreSQL.

Возможные ошибки при работе и способы их устранения. При эксплуатации программного средства пользователь может столкнуться с типовыми ситуациями:

- неверный логин или пароль при входе в систему;
- попытка сохранить запись без обязательных полей;
- ввод отрицательных числовых значений;
- попытка оформить конфликтующую сделку;
- попытка удалить запись, используемую в связанных таблицах;
- отсутствие подключения к базе данных при запуске приложения.

В перечисленных случаях система выводит сообщение об ошибке и не выполняет некорректную операцию. Для устранения проблемы рекомендуется:

- проверить правильность логина и пароля;
- убедиться в заполнении всех обязательных полей формы;
- проверить корректность дат и числовых значений;
- убедиться, что объект недвижимости доступен для оформления сделки;
- при ошибках запуска проверить настройки `DATABASE_URL`, состояние сервера PostgreSQL и наличие клиентских утилит в `PATH`.

Таким образом, разработанное программное средство предоставляет пользователю завершенный набор средств для повседневной работы с данными агентства недвижимости, формирования отчетности и выполнения административных операций сопровождения.
